## [COMMON-122] Primary Key, Candidate Key, Foreign Key, Unique Key의 차이에 대해 설명해 주세요.

답변:

먼저 Primary Key는 기본키로 최소성과 유일성을 만족하면서 테이블 내의 하나의 데이터를 고유하게 식별할 수 있는 키입니다.

후보키Candidate Key는 최소성과 유일성을 만족하지만 Primary Key가 아닌 나머지 키를 의미합니다.

Foreign Key는 데이터베이스 내에 다른 테이블의 기본키를 참조하는 키이며, 테이블 간의 연관관계를 매핑할 때 사용됩니다.

Unique Key는 유일성을 만족하는 키를 의미합니다.

## [COMMON-123] 정규화가 무엇이고, 정규화를 하지 않으면 어떤 이상 현상이 발생하는지 설명해 주세요.

답변:

정규화는 데이터의 중복과 정합성을 제거하기 위해 테이블을 분해함으로써 논리적으로 구조화하는 과정을 의미합니다.

주로 데이터를 관리하는 과정에서 발생하는 이상 현상을 방지하는 데에 목적이 있습니다.

이 이상 현상에는 크게 3가지가 있는데, 삽입 이상, 삭제 이상, 갱신 이상이 있습니다.

먼저 삽입 이상이란, 데이터를 삽입하는 과정에서 원하지 않는 값까지 넣어야 하는 문제를 의미합니다.

삭제 이상이란, 데이터를 삭제하는 과정에서 의도하지 않는 값까지 삭제가 되는 문제를 의미합니다.

갱신 이상이란, 데이터를 수정하는 과정에서 일부 데이터만 수정이 되고, 나머지는 수정되지 않아 정보 불일치가 발생하는 문제를 의미합니다.

## [COMMON-125] Join이 무엇이고, Inner Join과 Outer Join의 차이를 설명해 주세요.

답변:

Join이란, 두 테이블을 공통된 열을 기준으로 합쳐서 조회하는 연산을 의미합니다.

Inner Join은 두 테이블에서 조인 조건이 만족하는 데이터만 조회하는 방식입니다.

Outer Join은 두 테이블에서 조인 조건이 만족하지 않아도 각 테이블의 다른 열도 모두 함께 조회하는 방식입니다. 이때, 서로 다른 테이블에 열에 대한 값이 없으면 기본적으로 NULL 값이 포함됩니다.

## [COMMON-126] 인덱스가 무엇이고, 왜 조회 성능을 향상시키는지 설명해 주세요.

답변:

인덱스란, 테이블의 데이터를 빠르게 찾기 위해 실제 데이터의 위치를 별도의 자료구조로 저장하는 방식을 의미합니다.

따라서 인덱스가 없을 때 조회하는 쿼리문을 입력하면 테이블의 모든 데이터를 순차적으로 탐색하지만,

인덱스가 있는 경우 인덱스에서 먼저 값을 찾은 후, 해당 인덱스가 가리키는 실제 데이터의 위치에 접근함으로써 조회 성능을 향상시킬 수 있습니다.

## [COMMON-127] B-Tree와 B+Tree에 대해 설명하고, DB 인덱스에서 B+Tree가 많이 사용되는 이유를 설명해 주세요. ⭐

답변:

B-Tree와 B+Tree는 인덱스에 활용되는 자료구조인데, 먼저 B-Tree는 하나의 노드가 여러 개의 키 값과 자식 노드를 가질 수 있는 트리구조입니다. 기본적으로 모든 키 값이 정렬되어있고, 모든 리프 노드의 깊이가 같은 균형 트리입니다.

B+Tree는 오직 리프 노드에만 키와 데이터를 저장하고 리프 노드끼리는 연결리스트로 연결하고, 그 위의 부모 노드에는 모두 탐색 방향을 결정하는 값만 저장되어있는 구조입니다.

B+Tree는 탐색을 하거나 데이터를 저장하는 관점에서 B-Tree보다 더 큰 장점을 가집니다.

우선 데이터가 리프 노드에만 저장되기 때문에 트리의 높이가 낮아져 필요한 메모리 공간이 적어지고, 데이터의 범위 탐색 및 순차 조회 시 리프 노드만 탐색하면 되기 때문에 인덱스에 많이 사용됩니다.

## [COMMON-128] 복합 인덱스에서 컬럼 순서가 중요한 이유를 설명해 주세요.

답변:

복합 인덱스는 이 인덱스를 활용하는 실제 쿼리에서 조건이 어떻게 사용되는지에 따라 조회 성능에 영향을 줄 수 있습니다.

만약, A와 B 열을 활용하여 복합 인덱스를 생성했다고 했을 경우, A를 기준으로 인덱스가 먼저 정렬되고, 그 이후에 A가 정렬된 상태로 B 열의 인덱스가 정렬됩니다.

하지만, 데이터를 조회할 때 B열의 조건이 먼저 사용되고, A열의 조건이 그 다음에 사용된다면 B 조건을 탐색하고 A 조건을 탐색할 때는 B 조건의 범위와는 별개로 탐색해야 하기 때문에 인덱스를 효율적으로 탐색하기가 어렵습니다.

따라서 복합 인덱스를 사용할 경우, 실제 쿼리에서 범위 조건, 동등 조건, 조건의 순서 등을 고려하는 것이 중요합니다.

## [COMMON-130] 트랜잭션이 무엇이고, ACID에 대해 설명해 주세요.

답변:

트랜잭션이란, 데이터의 처리 작업이 이루어지는 하나의 논리적인 단위를 의미합니다.

이 트랜잭션의 ACID라는 특징을 갖는데, 이는 원자성, 일관성, 격리성, 지속성이 있습니다.

원자성이란, 트랜잭션의 결과는 모두 성공하거나 모두 실패해야 한다는 특징을 의미합니다.

일관성이란, 트랜잭션이 완료된 이후에도 데이터베이스의 규칙이나 관리에 문제가 발생하지 않아야 하는 것을 의미합니다.

격리성이란, 트랜잭션이 진행되는 과정에 다른 트랜잭션이나 데이터에 영향을 주어서는 안된다는 것을 의미합니다.

지속성이란, 트랜잭션이 완료된 결과는 영구적으로 반영되어야 하는 것을 의미합니다.

## [COMMON-131] 트랜잭션 격리 수준에 대해 설명해 주세요.

답변:

트랜잭션 격리 수준은 여러 트랜잭션이 동시에 발생할 때, 다른 트랜잭션의 변경 내용을 어디까지 허용할지를 나타내는 기준입니다.

크게 Read Uncommitted, Read Committed, Repeatable Read, Serializable로 4단계로 나누어져있습니다.

먼저 Read Uncommitted는 아직 반영되지 않은 트랜잭션의 변경 내용도 읽을 수 있는 가장 낮은 격리 수준입니다. 트랜잭션의 동시 처리 성능은 매우 높지만, 데이터의 일관성에는 가장 취약하다는 특징이 있습니다.

Read Committed는 커밋된 트랜잭션만 읽을 수 있는 것을 의미합니다. 따라서 트랜잭션의 이상 현상 중, Dirty Read를 방지할 수 있습니다.

Repeatable Read는 한 트랜잭션 안에서 같은 데이터를 여러번 읽더라도 값이 똑같이 유지되는 것을 의미합니다.

Serializable은 트랜잭션을 동시에 처리하는 것이 아닌 순차적으로 처리하도록 하는 가장 높은 격리 수준입니다.

## [COMMON-132] Dirty Read, Non-repeatable Read, Phantom Read에 대해 설명해 주세요.

답변:

Dirty Read, Non-repeatable Read, Phantom Read는 트랜잭션에서 발생하는 데이터 이상 현상을 의미합니다.

우선 Dirty Read는 한 트랜잭션이 아직 커밋 되지 않은 다른 트랜잭션의 데이터를 읽는 문제를 의미합니다. 따라서 다른 트랜잭션이 롤백되는 경우, 결국 잘못된 데이터를 읽는 문제로 이어질 수 있습니다.

Non-repeatable Read는 하나의 트랜잭션 내에서 같은 데이터를 두 번 읽었을 때, 데이터의 조회 결과가 달라지는 현상을 의미합니다.

Phantom Read는 하나의 트랜잭션 내에서 같은 데이터를 두 번 읽었을 때, 다른 트랜잭션의 수정 작업으로 인해 조회되는 데이터의 개수가 달라지는 현상을 의미합니다.

## [COMMON-133] DB Lock이 무엇이고, Shared Lock과 Exclusive Lock의 차이에 대해 설명해 주세요.

답변:

DB Lock이란, 여러 트랜잭션이 같은 데이터를 동시에 접근할 때, 이를 제어하는 수단을 의미합니다.

공유 락은 데이터를 읽기 위해 설정하는 락을 의미합니다. 두 트랜잭션이 데이터를 동시에 읽는 것은 문제가 되지 않으므로, 이 공유 락을 얻어 함께 읽을 수 있지만, 공유 락이 걸린 데이터는 다른 트랜잭션이 수정할 수 없습니다.

배타적 락은 데이터를 수정하기 위해 설정하는 락을 의미합니다. 이는 다른 트랜잭션이 데이터의 수정작업을 하는 것을 보호하기 때문에, 배타적 락이 걸린 데이터는 다른 트랜잭션이 읽기나 수정을 할 수 없습니다.

## [COMMON-134] Optimistic Lock과 Pessimistic Lock의 차이에 대해 설명해 주세요.

답변:

Optimistic Lock고 Pessimistic Lock은 두 트랜잭션 간에 동시성 문제가 발생할 때 이를 처리하는 방식을 의미합니다.

Optimistic Lock은 충돌이 자주 발생하지 않을 것이라는 전제 하에 기본적으로 락을 걸지 않고, 충돌을 감지하고 이를 해결하는 방식입니다.

Pessimistic Lock은 두 트랜잭션 간에 동시성 문제가 발생할 가능성이 높다는 전제 하에 이를 처리하는 방식을 의미합니다.

따라서 해당 트랜잭션에서 해당 데이터에 대한 작업이 시작될 때 락이 걸리고, 다른 트랜잭션이 해당 데이터에 접근하는 경우 이를 대기시키는 방식입니다.

## [COMMON-136] Connection Pool이 무엇이고, 왜 필요한지 설명해 주세요.

답변:

커넥션 풀이란, 데이터베이스와의 연결을 미리 만들어두고, 애플리케이션이 필요할 때 이 자원을 사용하여 데이터베이스에서 작업을 수행한뒤 반환할 수 있도록 하는 관리 구조를 의미합니다.

커넥션 풀을 사용하지 않는 경우, 애플리케이션이 데이터베이스에 접근해야 할 때마다 새로운 커넥션을 생성해야 하는 문제가 발생합니다. 그리고 이러한 커넥션의 개수를 제한하지 않으면 데이터베이스에 접근하는 많은 트래픽이 생기는 문제가 발생할 수 있습니다.

## [COMMON-137] Cache를 사용하는 이유와 주의해야 할 점을 설명해 주세요.

답변:

캐시는 메모리 계층 구조가 낮은 위치에서 데이터를 읽는 과정에서 발생하는 성능을 개선하기 위해 사용됩니다. 예를 들어 자주 조회되는 데이터의 경우, 매번 디스크에서 데이터를 읽지 않고, 데이터를 메모리에 저장해두고 읽음으로써 데이터를 읽는 속도를 개선할 수 있습니다.

캐시를 사용할 때 주의해야 할 것은 정합성 문제입니다. 특정 데이터가 원본과 캐시에 모두 저장되어있을 경우, 이 데이터의 수정 작업이 발생할 때 어느 한 곳에만 작업이 진행되면 데이터의 정합성이 깨지는 문제가 발생할 수 있습니다.

따라서 캐시를 사용할 때는 데이터의 수정 작업이 발생할 경우, 정합성을 유지하기 위한 정책이 중요합니다.

## [COMMON-138] Cache Aside 패턴에 대해 설명해 주세요. 

답변:

Cache Aside 패턴이란, 애플리케이션이 캐시 데이터베이스를 관리하는 패턴을 의미합니다.

따라서 특정 데이터에 접근하는 경우 우선 캐시를 조회하여 데이터를 확인하고, hit이 발생한 경우에는 캐시에서 바로 데이터를 읽습니다.

하지만 만약 miss가 발생하는 경우, 데이터를 조회하기 위해 데이터베이스에 접근하고, 이를 캐시에 반영하는 방식입니다.

## [COMMON-139] Redis와 같은 In-memory DB를 사용하는 이유를 설명해 주세요.

답변:

Redis는 메모리 계층에 데이터를 임시적으로 저장하여 읽고, 수정할 때 이를 활용함으로써 기존에 디스크에 접근하는 것보다 더 효율적으로 데이터에 접근하기 위해 사용합니다.

따라서 Redis를 통해 자주 사용되는 데이터를 메모리에 저장해둠으로써 데이터를 읽어오는 성능을 향상시킬 수 있고, 데이터베이스에 접근하는 트래픽을 분산시킬 수 있다는 장점이 있습니다.

## [COMMON-140] SQL Injection이 무엇이고, 어떻게 방어할 수 있는지 설명해 주세요.

답변:

SQL Injection이란, 사용자가 입력값에 SQL 명령의 일부분을 넣어 데이터베이스가 해당 쿼리를 수행할 때 악의적으로 데이터를 조작하게 만드는 공격하는 방식을 의미합니다.

이를 방어할 수 있는 대표적인 방법으로는 파라미터 바인딩이 있습니다. 파라미터 바인딩은 SQL 명령과 사용자의 입력값을 코드 레벨에서 분리하는 방식으로, 이를 통해 사용자의 입력값이 SQL로 수행되지 않고, 문자열 입력값으로 처리되기 때문에 SQL Injection을 방어할 수 있습니다.
