## [COMMON-121] RDB와 NoSQL의 차이에 대해 설명해 주세요.

답변:

RDB는 데이터를 테이블 형태로 저장하고 테이블 간의 관계를 통해 데이터를 관리하는 데이터베이스 입니다.

NoSQL은 관계형 모델에 얽매이지 않고 Key-Value, Graph 등 다양한 형태로 데이터를 저장하는 데이터베이스입니다.

RDB는 고정된 스키마와 SQL을 사용하고, ACID 트랜잭션을 지원하기 때문에 데이터의 무결성과 일관성이 중요한 서비스에 적합합니다. 반면에 NoSQL은 유연한 스키마를 가지고 있어 수평 확장에 강점이 있습니다. 또한 대용량 데이터를 빠르게 처리하기에 적합합니다. 따라서 금융이나 주문 시스템에는 RDB가 캐시나 로그, SNS와 같이 대규모 트래픽과 확장성이 중요한 서비스에는 NoSQL이 사용됩니다.

## [COMMON-122] Primary Key, Candidate Key, Foreign Key, Unique Key의 차이에 대해 설명해 주세요.

답변:

- Candidate Key는 후보키로 유일성과 최소성을 만족하는 키입니다. 후보키로 설정될 수 있는 키는 여러 개 일 수 있습니다.
- Primary Key는 후보키 중에서 선택한 메인 키로 유일성과 최소성을 만족하며 NULL 값을 가질 수 없습니다.
- Foreign Key는 외래키로 다른 테이블의 기본키를 참조하는 키입니다.
- Unique Key는 모든 레코드에 대해 유일한 값을 가져야 하는 키입니다. 하나의 테이블에 여러 개의 유니크 키를 설정할 수 있습니다.

## [COMMON-127] B-Tree와 B+Tree에 대해 설명하고, DB 인덱스에서 B+Tree가 많이 사용되는 이유를 설명해 주세요.

답변:

- B-Tree는 균형을 유지하는 다진 탐색트리로서 루트를 포함한 모든 노드에 데이터가 저장될 수 있습니다. 하나의 노드에 여러 개의 Key를 저장할 수 있고 여러 개의 자식을 가질 수 있습니다.
- B+Tree는 B-Tree를 개선한 구조로 가장 큰 차이는 실제 데이터가 리프 노드에만 저장한다는 점입니다. 내부 노드에는 실제 데이터가 아니라 검색을 위한 Key만 가지고 있습니다. 이 리프 노드가 모두 연결되어 있어 범위 조회가 굉장히 빠릅니다.
- 데이터 베이스 인덱스는 범위 조회와 정렬 조회가 자주 발생하고 디스크 I/O를 최소화하는 것이 중요하기 때문에 내부 노드에 더 많은 Key를 저장할 수 있고 리프 노드를 순차적으로 탐색할 수 있는 B+Tree를 주로 사용합니다.

## [COMMON-130] 트랜잭션이 무엇이고, ACID에 대해 설명해 주세요.

답변:

- 트랜잭션이란 하나의 논리적인 작업 단위를 의미합니다. 트랜잭션은 모든 작업이 성공적으로 완료되거나, 문제가 발생하면 모두 취소되어야 합니다.
- Atomicity(원자성)은 트랜잭션이 모두 성공하거나, 모두 실패해야 함을 보장합니다.
- Consistency(일관성)은 트랜잭션이 실행되기 전과 후에 데이터베이스는 항상 일관성을 유지해야 한다는 것입니다.
- Isolation(격리성)은 하나의 트랜잭션이 실행 중일 때, 다른 트랜잭션이 해당 작업에 영향을 주지 않도록 해야 합니다. 여러 트랜잭션이 동시에 실행될 때도 각 트랜잭션이 독립적으로 실행된 것과 동일한 결과를 보장합니다.
- Durability(영속성)은 트랜잭션이 성공적으로 커밋되면 해당 변경 내용은 영구적으로 반영되어야 한다는 것입니다.

## [COMMON-132] Dirty Read, Non-repeatable Read, Phantom Read에 대해 설명해 주세요.

답변:

- Dirty Read는 트랜잭션 A에서 아직 커밋하지 않은 데이터가 트랜잭션 B에서 보이는 현상입니다.
- Non-Repeatable Read는 하나의 트랜잭션에서 같은 데이터를 2번 조회할 때, 두 결과가 다르게 나타나는 현상입니다.
- Phantom Read는 하나의 트랜잭션에서 일정 범위의 데이터를 2번 조회할 때, 첫번째 조회 결과엔 없던 데이터가 두번째 조회 결과에서 나타나는 현상입니다.

## [COMMON-133] DB Lock이 무엇이고, Shared Lock과 Exclusive Lock의 차이에 대해 설명해 주세요.

답변:

- DB Lock은 여러 트랜잭션이 동시에 같은 데이터를 접근할때 데이터의 무결성과 일관성을 보장하기 위해 사용하는 동시성 제어 기법입니다
- shared lock은 데이터를 읽기 위한 lock으로 여러 트랜잭션이 동시에 획득 가능하지만 수정은 허용하지 않습니다.
- 반면 exclusive lock은 데이터를 수정하기 위한 lock으로 한 트랜잭션만 획득할 수 있으며 다른 트랜잭션의 읽기와 쓰기는 모두 차단합니다. 이를 통해 race condition 같은 문제는 방지 가능하나 동시성이 감소하거나 Deadlock이 발생할 수 있습니다.

## [COMMON-134] Optimistic Lock과 Pessimistic Lock의 차이에 대해 설명해 주세요.

답변:

- Pessimistic Lock은 충돌이 발생할 가능성이 높다고 가정하고 데이터를 읽거나 수정할 때부터 Lock을 걸어 다른 트랜잭션의 접근을 제한하는 방식입니다. 그렇기 때문에 충돌을 미리 방지해 데이터 정합성이 높지만 Lock 대기 발생, 동시성 감소, 데드락 가능성이 있습니다.
- Optimistic Lock은 충돌이 거의 발생하지 않는다고 가정하고 Lock을 걸지 않은 채 작업한 뒤, 저장 시점에 충돌 여부를 확인하는 방식입니다. 반대로 동시성이 높고 데드락 가능성이 적지만 충돌 시 재시도가 필요하고 충돌이 잦게 되면 성능이 저하됩니다.
- 그래서 충돌이 발생하면 안되는 콘서트 좌석 예약, 금융 관련은 Pessimistic Lock을 사용하고 일반 CRUD 서비스, 게시글 수정과 같은 동시 수정 가능성이 낮은 경우는 Optimistic Lock을 사용합니다.

참고 자료:

## [COMMON-135] DB Deadlock이 발생하는 상황과 해결 방법에 대해 설명해 주세요.

답변:

- DB 데드락은 두 개 이상의 트랜잭션이 서로가 가진 Lock이 해제되기만을 기다리며 영원히 진행하지 못하는 상태를 말합니다. 예를 들어 한 트랜잭션은 A 테이블을 먼저 잠근 뒤 B 테이블을 요청하고 다른 트랜잭션은 B를 먼저 잠근 뒤 A를 요청하며 데드락이 발생할 수 있습니다.

    - 트랜잭션이 필요한 모든 락을 한번에 요청하게끔 합니다.

    - 트랜잭션 타임아웃을 설정해 잠재적 데드락을 감지합니다.
    - 테이블 수준이 아닌 행 수준의 세분화된 락을 사용합니다

## [COMMON-136] Connection Pool이 무엇이고, 왜 필요한지 설명해 주세요.

## [COMMON-137] Cache를 사용하는 이유와 주의해야 할 점을 설명해 주세요.

답변:

- Cache는 자주 사용되는 데이터를 빠른 저장소에 저장해두고 요청이 들어오면 DB 대신 캐시에서 조회하는 기술입니다.
- Cache를 사용하는 가장 큰 이유는 성능 향상입니다. DB 조회는 디스크 접근, 네트워크 통신 등의 비용이 발생합니다. 반면 캐시는 메모리에 저장되어 있기 때문에 조회 속도가 훨씬 빠릅니다.
- Cache를 사용할 때 주의점은 캐시와 DB의 데이터가 달라질 수 있다는 점입니다. 이를 캐시 불일치라고 합니다. 이를 위해 데이터 변경 시 캐시를 함께 갱신, 삭제 해줘야 합니다.

## [COMMON-138] Cache Aside 패턴에 대해 설명해 주세요.

답변:

Cache Aside Pattern은 애플리케이션이 캐시를 먼저 조회하고 캐시에 데이터가 없으면 DB에서 조회한 뒤, 캐시에 저장하는 방식입니다.

데이터가 자주 변경되지는 않지만, 조회 요청이 많은 경우에 사용됩니다. 또한 캐시 적중률이 높고 실시간성이 크게 요구되지 않는 경우에 적절합니다. 

예를 들어 네이버 웹툰의 인기 작품 목록 조회처럼 자주 조회되지만 실시간으로 자주 바뀌진 않는 곳에 자주 사용됩니다.

## [COMMON-139] Redis와 같은 In-memory DB를 사용하는 이유를 설명해 주세요.

답변:

In-memory DB란 디스크에 저장되는 데이터베이스와는 다르게 메모리에 데이터를 저장 하는 데이터베이스를 말합니다. 

따라서 조회가 많은 데이터를 캐싱하여 DB 부하를 줄이고 응답 속도를 향상시키는 데 많이 사용됩니다. 또한 세션 저장, 실시간 랭킹, 분산 락, Pub/Sub 등 다양한 용도로 활용됩니다. 다만 메모리 비용이 높고 휘발성이므로 캐시나, 보조 저장소로 함께 사용됩니다.

## [COMMON-140] SQL Injection이 무엇이고, 어떻게 방어할 수 있는지 설명해 주세요.

답변:

SQL 인젝션은 악의적인 SQL 질의문을 삽입해 데이터베이스가 의도되지 않은 비정상적 동작을 하도록 조작하는 공격 기법입니다.

문자열 연결 방식으로 SQL을 생성할 때 주로 발생하며 로그인 우회나 데이터 조회, 수정, 삭제 등의 피해를 일으킬 수 있습니다.

가장 효과적인 방어 방법은 Prepared Statement를 사용하여 SQL과 입력 데이터를 분리하는 것입니다. 또한 ORM을 활용하고 입력값 검증, 최소 권한 원칙 적용을 통해 보안을 강화할 수 있습니다.
