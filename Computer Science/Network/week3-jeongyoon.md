## [COMMON-081] OSI 7계층과 TCP/IP 4계층을 비교해 설명해 주세요.

답변: TCP/IP가 OSI 모델보다 먼저 개발되었으며 두 모델 모두 계층형이짐나 서로의 계층이 정확히 일치하진 않습니다.

TCP/IP는 인터넷 개발 이후 계속 표준화되어 신뢰성이 높은 편이지만 OSI 모델은 실제로 구현되는 예가 거의 없어서 신뢰성이 낮습니다. 또한 OSI 모델은 장비 개발과 통신 자체를 어떻게 표준으로 잡을지 개념적으로 사용되는 반면 실질적인 통신 자체는 TCP/IP 프로토콜을 활용합니다.

- **OSI 7 계층**
    
    ⑺ 응용 계층
    
    - 네트워크 자원에 사용자가 접근하는 방법을 제공하는 계층
    - 최종적으로 사용자가 볼 수 있는 유일한 계층
    - **`프로토콜`** HTTP, Telnet, DHCP, DNS, FTP
    
    ⑹ 표현 계층
    
    - 데이터의 변환 작업(인코딩, 디코딩, 암호화)를 하는 계층
    - 응용 계층의 데이터 표현에서 독립적인 부분을 나타냄
    - **`프로토콜`** ASCII, MPEG, JPEG, EBCDIC
    
    ⑸ 세션 계층
    
    - 응용 프로그램 간의 연결을 지원하는 계층
    - 사용자와 서버 간에 대화가 필요하면 세션을 만드는 작업을 처리
    - **`프로토콜`** SSH, TLS
    
    ⑷ 전송 계층
    
    - 서비스를 구분하고 데이터의 전송 방식을 담당하는 계층
    - 포트 번호를 사용하여 최종 도착지인 프로세스까지 데이터가 도달하게끔 함
    - 보낼 데이터의 용량, 속도, 목적지 등을 처리
    - 양 끝단의 사용자들이 신뢰성 있는 데이터를 주고 받을 수 있게 해 주어 상위 계층들이 데이터 전달의 유효성이나 효율성을 생각하지 않도록 함
    - **`프로토콜`** TCP, UDP, ARP
    
    ⑶ 네트워크 계층
    
    - 서로 다른 두 네트워크 간의 데이터 전송을 담당
    - 데이터에 논리적 주소인 IP 주소를 부여하고 데이터를 목적지까지 가장 안전하고 빠르게 전달하는 라우팅 기능을 함
    - 데이터를 연결된 다른 네트워크로 전달함으로서 인터넷이 가능하게 만드는 계층
    - **`프로토콜`** IP, ICMP, IGMP
    
    ⑵ 데이터 링크 계층
    
    - 컴퓨터와 컴퓨터 간 신뢰성 있는 전송을 보장하기 위한 계층
    - 물리 계층을 통해 송수신되는 정보의 오류를 검출하고 흐름을 관리
    - 데이터에 컴퓨터의 물리적 주소인 MAC 주소를 부여해 출처를 알 수 있게끔 함
    - **`프로토콜`** MAC, PPP, HDLC…
    
    ⑴ 물리 계층
    
    - 네트워크의 하드웨어 전송 기술로 구성
    - 전기적, 기계적, 기능적인 특성을 이용하여 통신 케이블로 데이터를 전송
    - **`프로토콜`** Ethernet, RS-232C
- **TCP/IP 4 계층**
    
    ⑷ Application Layer
    
    - OSI 계층에서 5,6,7 계층에 해당
    - 사용자가 응용프로그램과 소통할 수 있게 UI 제공
    - TCP/IP 기반 응용 프로그램을 구분할 때 사용
    
    ⑶ Transport Layer
    
    - OSI 계층에서 전송 계층에 해당
    - 데이터의 송수신을 담당하고 통신 노드 간의 연결 제어
    - 네트워크 양단의 송수신 호스트 사이에서 신뢰성 있는 전송기능 제공
    
    ⑵ Internet Layer
    
    - OSI 계층의 네트워크 계층에 해당
    - 논리적 주소인 IP를 이용한 노드간 데이터 전송과 라우팅 기능을 담당
    
    ⑴ Network Access Layer
    
    - 운영체제의 하드웨어적인 요소와 관련되는 모든 것을 지원하는 계층
    - 물리적으로 데이터가 네트워크를 통해 어떻게 전송되는지 정의
    - 에러 검출 기능과 패킷의 프레임화 기능을 담당

## [COMMON-084] TCP 4-way handshake가 무엇이고, 연결 종료 과정에서 TIME_WAIT이 필요한 이유를 설명해 주세요.

답변: TCP의 4-way-hankshake는 연결을 정상적으로 종료하기 위한 과정입니다. 먼저 연결을 종료하려는 측이 FIN을 보내고 상대방은 ACK를 보내 이를 확인합니다. 이후 상대방도 모든 데이턴 전송을 마치면 FIN을 보내고 마지막으로 처음 종료를 요청한 쪽이 ACK를 보내게 되면서 연결이 종료됩니다.

종료가 4단계인 이유는 TCP가 양방향 통신을 지원하므로, 각 방향의 연결이 독립적으로 종료해야하기 때문입니다. 또한 마지막 ACK를 보낸 쪽은 바로 종료하지 않고 TIME_WAIT 상태로 일정 시간 대기합니다. 마지막 ACK가 유실되어 혼동이 오지 않게 하기 위해서이고 지연 패킷에 대한 대처입니다.

## [COMMON-088] TLS/SSL Handshake가 어떤 역할을 하는지 설명해 주세요.

답변: TLS Handshake는 클라이언트와 서버가 HTTPS 통신을 시작하기 전에 서로 암호화 방식과 인증을 협상하는 과정입니다.

먼저 클라이언트와 서버는 사용할 TLS 버전과 암호화 알고리즘을 협상하고 서버는 인증서를 전달하여 자신의 신원을 증명합니다. 클라이언트는 인증서를 검증한 뒤 키 교환 과정을 통해 서버와 동일한 세션 키를 생성합니다. 이후 실제 데이터는 대칭키 방식으로 암호화하여 전송합니다. 

이를 통해 서버 인증, 안전한 키 교환, 데이터의 기밀성과 무결성을 보장할 수 있습니다.

## [COMMON-095] Stateless하다는 것이 무엇이고, HTTP가 Stateless한 것이 어떤 장단점을 가지는지 설명해 주세요.

답변: HTTP가 stateless 하다는 것은 서버가 클라이언트가 보내준 정보를 저장하지 않는다. 즉, 상태를 계속해서 보존하지 않는다는 의미입니다. 

stateful은 항상 같은 상태의 정보를 들고 있는 상태의 서버가 계속 지속되어야 합니다. 그래서 해당 서버가 오류가 나게 되면 처음부터 과정을 반복해야 합니다. 반면에 stateless는 상태 자체가 저장되지 않았기 때문에 아무 서버에게나 요청을 하면 됩니다. 수평 확장에 있어서 굉장히 유리하다는 장점을 가진다는 것입니다.

물론 상태를 유지해야 하는 경우인 로그인에서는 굉장히 취약합니다. stateless 특성상 서버에 유저에 대한 정보를 계속 유지 시키질 못하기 때문에 세션, 쿠키 등을 사용해 상태를 유지하는 방식을 사용하고 있습니다.

## [COMMON-096] CORS가 무엇이고, 왜 발생하는지 설명해 주세요.

## [COMMON-097] Blocking / Non-blocking과 Synchronous / Asynchronous의 차이에 대해 설명해 주세요.

## [COMMON-098] I/O Multiplexing이 무엇이고, 왜 필요한지 설명해 주세요.

답변: I/O 멀티플렉싱은 하나의 스레드가 여러 개의 I/O 작업을 동시에 감시하고 준비된 I/O만 처리하는 기술입니다.

일반적인 Blocking I/O에서는 연결마다 스레드가 필요해 많은 클라이언트가 접속하면 메모리 사용량과 Context Switch 비용이 크게 증가합니다. 반면 I/O Multiplexing은 하나의 스레드가 여러 소켓을 감시하다가 데이터가 준비된 소켓만 처리하므로 적은 수의 스레드로도 많은 연결을 효율적으로 처리할 수 있습니다.

참고 자료: https://velog.io/@hyopark/IO-Multiplexing

## [COMMON-099] WebSocket이 무엇이고, HTTP와 어떤 차이가 있는지 설명해 주세요.

답변: websocket은 클라이언트와 서버가 하나의 연결을 유지하면서 양방향으로 실시간 데이터를 주고 받을 수 있는 통신 프로토콜입니다.

HTTP는 리퀘스트가 있어야 리스폰스가 발생하고 클라이언트가 먼저 요청을 해야 서버가 응답을 할 수 있지만, 웹소켓은 연결을 유지하며 양방향 통신이 가능합니다. 그래서 채팅, 실시간 알림과 같은 실시간 서비스에 웹소켓이 사용됩니다.

## [COMMON-100] Load Balancing이 무엇이고, 어떤 방식들이 있는지 설명해 주세요.

답변: 로드밸런싱은 네트워크 또는 서버에 가해지는 부하 트래픽을 분산시켜주는 기술을 의미합니다.

대표적인 방식에는 첫 번째, 라운드 로빈 방식이 존재합니다. 가장 기본적으로 순서대로 서버에 요청을 보냅니다. 구현이 단순하지만 서버 성능 차이를 고려하지 못하는 단점이 있습니다.

두 번째로는 weighted 라운드 로빈 방식이 있습니다. 서버마다 가중치를 부여하여 성능이 좋은 서버에 더 많은 요청을 보냅니다. 

또 IP 해시 방식이 있습니다. 클라이언트의 IP 주소가 어떤 서버로 클라이언트의 요청이 전달될지 결정합니다.

least connections 방식은 현재 연결 수가 가장 적은 서버로, least response time은 가장 적은 연결 수와 가장 짧은 응답 서버에 우선적으로 요청을 보냅니다.
