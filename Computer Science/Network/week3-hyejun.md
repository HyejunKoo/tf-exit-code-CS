## [COMMON-083] TCP 3-way handshake가 무엇이고, 왜 필요한지 설명해 주세요.

답변: 클라이언트가 SYN을 보내고, 서버가 SYN, ACK으로 응답한 뒤, 클라이언트가 ACK을 보내 TCP연결을 설정하는 과정. 양쪽이 통신 가능한 상태인지 확인하고 초기 순서 번호 공유하기 위해 필요

## [COMMON-084] TCP 4-way handshake가 무엇이고, 연결 종료 과정에서 TIME_WAIT이 필요한 이유를 설명해 주세요.

답변: 연결 종료 시 한쪽이 FIN을 보내면 상대가 ACK을 보내고, 상대도 FIN을 보낸 뒤 마지막 ACK을 받아 연결 종료. TIME_WAIT은 마지막 ACK가 유실됐을 때 다시 전송하고, 이전 연결의 지연된 패킷이 새 연결에 섞이는 것을 방지하기 위해 필요.
*3-Way Handshake는 TCP연결을 시작할 때, 4-Way Handshake는 TCP연결을 종료할 때 사용.

## [COMMON-089] DNS가 무엇이고, 도메인 이름이 IP 주소로 변환되는 과정을 설명해 주세요.

*google.com → .com이 TLD

## [COMMON-095] Stateless하다는 것이 무엇이고, HTTP가 Stateless한 것이 어떤 장단점을 가지는지 설명해 주세요.

답변: stateless는 서버가 이전 요청의 사용자 상태를 기억하지 않고, 각 요청을 독립적으로 처리하는 특성. 서버 확장과 장애 대응이 쉽지만 로그인 상태 등을 유지하려면 cookie, session, token같은 별도 방식 필요

## [COMMON-096] CORS가 무엇이고, 왜 발생하는지 설명해 주세요.

답변: 다른 출처의 웹 페이지(브라우저가 다른. 대표적으로 백엔드 url -> 프론트 url) 가 서버 자원에 접근할 수 있도록 허용 범위를 정하는 정책. 브라우저의 동일 출처 정책 때문에 출처가 다른 요청이 제한되어 서버가 적절한 CORS 응답 헤더를 반환해야 허용된다.
